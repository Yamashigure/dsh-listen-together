## 它做什么

- **读取正在播放的声音**：从默认输出设备采回环音频（系统混音），不需要 Stereo Mix，也不需要指定播放器。你在浏览器里放 B 站，它就听同一路声音。
- **悬浮窗**：置顶、无边框、可拖动，显示当前应用、曲目、响度波形，带暂停和音量。音量直接改来源应用的音频会话（WASAPI），暂停走系统媒体命令。
- **让会话读到音乐**：Host 插件注册三个工具——`listen_now`、`listen_feel` 和 `listen_control`。任何会话都能问「现在在听什么」，也能让助手替你暂停、调音量。
- **手动的一句感受**：你在会话里问「这首歌给你的感觉怎么样？」这类问题时，助手才会用 `listen_feel` 读一下当前的曲目、响度、起伏和频段，再按自己的话说。插件不会自己往会话里递消息。
- **语音听写**：播放中每分钟左右切一段十秒的回环音频，交给本地的 SenseVoice 语音识别，把听到的字作为歌词参考塞进音乐状态里。混着伴奏的歌，识别结果会比较碎，当作「隐约听到」就好。
- **面板上的小按钮**：标题栏里“编辑”标签右边（左上角那片空位）有一枚耳机按钮，点一下开关悬浮窗；旁边的小齿轮打开外观设置（透明度、鼠标穿透、背景图）。按钮走宿主命令 `listen-together`，不依赖网页的 fetch；刚装好或改过客户端之后，刷新一次页面才会出现。
- **拖边缘改大小**：悬浮窗的四条边和四个角都能拖，靠近时光标会变双箭头；锁定后不响应拖拽。内容不跟着缩放，多出来的空间给波形和音量条。
- **标题太长会滚动**：曲名超出标题框时，不再用省略号截断，而是在标题框里自动横向滚动；开头停一下，慢慢走到结尾，停一下再回来。
- **标题会跟着换歌更新**：播放中大约每 1.2 秒核对一次浏览器窗口标题；新标题连续两次一致才替换，避免切到别的页面时把曲名顶掉。换歌后一般两三秒内更新。
- **波形样式**：面板里能给波形单独选颜色和透明度（0–100%）。颜色点“应用”生效，透明度松开滑条生效；都写进 `ui.ini` 的 `wavecolor` / `waveopacity`。暂停时波形会比播放时更淡。
- **背景位置**：面板里选好图后点“调整位置”，悬浮窗进入调整模式，直接拖动背景，右上角出现“确定”；点确定保存并退出。位置记在 `ui.ini` 的 `bgx/bgy` 里。调整时会临时解锁，确定后恢复原来的锁定状态。

## 安装（beta）

1. 在 DSH 桌面端打开 **Plugins → Add plugin**。
2. 粘贴本仓库的 GitHub 地址（或者下载 Release 里的 `.tgz`，把绝对路径填进去）。
3. 选 **Install**，装好后选 **Enable now**。
4. 第一次启动会编译原生辅助程序，需要 Windows 自带的 .NET Framework 4.x `csc.exe`。编译完成后悬浮窗会出现在屏幕右下角。

beta 没有发布到 npm，不要用包名安装。原生辅助程序没有签名，部分安全软件可能会拦；确认来源后再放行。

## 用法

装好以后悬浮窗会出现在屏幕右下角。拖动空白处可以挪位置，滚轮调音量，右上角 × 收起，`Ctrl+Alt+M` 再叫出来。小锁按钮锁上后，除了小锁本身，整只窗都会让鼠标穿过去，防止误碰暂停和音量；`Ctrl+Alt+L` 也能解锁。

| 操作 | 作用 |
| --- | --- |
| 播放/暂停按钮 | 向来源窗口发系统媒体命令 |
| 音量滑条 | 改来源应用的音频会话音量（不是系统总音量） |
| 滚轮 | 音量 ±4 |
| 拖边缘/四角 | 改悬浮窗大小，内容保持原尺寸不缩放；锁上时不响应 |
| 调整背景 | 面板点“调整位置”，在悬浮窗里拖动背景，点“确定”保存 |
| 波形颜色/透明度 | 面板里选颜色、拖透明度滑条；颜色点“应用”，透明度松开生效 |
| 小锁 | 鼠标穿透；只有小锁本身还能点 |
| 面板耳机按钮 | 显示/收起悬浮窗 |
| 面板小齿轮 | 透明度、背景图、穿透开关 |

在会话里可以说：

- 「我现在在听什么？」→ 助手调用 `listen_now`
- 「这首歌给你的感觉怎么样？」→ 助手调用 `listen_feel`
- 「帮我暂停一下 / 声音小一点」→ 助手调用 `listen_control`

插件不会主动递话；不问就没有音乐相关的内容进入会话。

## 已知边界

- **Windows only**：靠 WASAPI 和 Win32，别的平台没有实现。
- **系统混音，不是单窗口隔离**：Windows 的回环采集拿的是整个输出设备的声音。同时有别的软件在响，会一起被采进去；来源应用是通过音频会话挑出来的（浏览器优先、正在出声的优先）。
- **曲目名来自浏览器窗口标题**：系统混音分不出是哪个标签页在响；插件读当前窗口标题，再按媒体关键词过滤。播放中会定时核对，但如果播放器在后台标签页、当前标签页是别的页面，曲名可能对不上。真正的「正在播放」元数据要走系统媒体会话（SMTC），需要 Windows SDK 的 WinRT 投影，这一版没有接进来。
- **暂停依赖来源应用对系统媒体命令的响应**：Chromium 系（Chrome / Edge）一般没问题；个别播放器不响应时，只能手动按。
- **悬浮窗是独立的原生窗口**：不在 DSH 页面里，不会跟着主题切换；它自己有深色样式。它是一个普通的顶层窗口（没有工具窗口样式），所以 OBS 的“窗口采集”能把它加成素材；任务栏按钮用 `ITaskbarList` 去掉了，不会占一格。Alt+Tab 里可能在也可能不在，不影响采集。锁定后点击穿透，避免误碰。
- **反作弊**：这是一个独立进程，没有注入、钩子、内存读写、远程线程或驱动。它只做 WASAPI 回环、按应用调音量、读窗口标题/进程名（`PROCESS_QUERY_LIMITED_INFORMATION`，进程名缓存 60 秒，且只读浏览器窗口的标题）、以及暂停时发一次系统媒体键。没有任何工具能保证某个反作弊不误判；如果游戏的反作弊非常激进，最稳的做法还是听歌和游戏不同时开。
- **听写不是歌词**：SenseVoice 是语音识别模型，不是音乐分离；伴奏一响，人声会被糊住，结果可能是碎片或空。它只作为参考片段，不作为准确歌词展示。干净机器上第一次启用语音识别需要下载模型（约 239 MB）。
- **beta 阶段的已知问题**：面板按钮走宿主命令，会在会话日志里留下命令事件（不是聊天消息）；后续版本会换成不写会话的桥。原生辅助程序在第一次启用时用 `csc` 编译，未签名；自动评论已经移除，只保留手动触发。

## 隐私

- 回环音频只在本机处理，语音识别用的是本地 SenseVoice 模型；插件不上传音频，也不申请麦克风。
- 听写文本只作为本地音乐状态保存；当你在会话里问起、助手调用 `listen_feel` 时，它会作为工具结果进入当前会话，和普通对话一样交给模型服务。
- 会话里只会拿到当前曲目、响度/频段走势、听写片段和来源进程名，以及你在会话里主动提问时助手读到的内容。
- 悬浮窗位置、大小、外观选项存在 `%LOCALAPPDATA%\dsh-listen-together\ui.ini`；不收集账号、不扫描文件、不读浏览历史。
- `traceFile` 默认留空，不写排查日志；需要排查时可以在插件配置里指定一个本地路径，自己确认内容后再分享。

## 配置

在插件页面或 `cordis.patch.yml` 里改：

```yaml
app: ''                 # 固定来源进程，例如 msedge.exe；留空自动跟随
showWindow: true        # 启动时显示悬浮窗
lyrics: true            # 是否把回环音频切段送进语音识别
sttClipSeconds: 10      # 每段听写多长（4-20 秒）
sttEveryMinutes: 1      # 两段听写之间至少隔多久
traceFile: ''           # 排查日志路径，留空不写
```

## 开发

原生部分在 `native/`，是单个 C# WinForms 程序，没有第三方依赖；Host 在 `index.js`，客户端在 `client.js`。bundle 的 patch 在 `cordis.patch.yml`，会插入语音识别的两个 Host 行。

第一次启用时，Host 会用系统自带的 `csc.exe` 把 `native/*.cs` 编译到 `%LOCALAPPDATA%\dsh-listen-together\`，之后启动直接复用。
